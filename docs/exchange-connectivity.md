# Noryx Exchange Connectivity

Noryx Exchange Connectivity provides the integration layer between the Noryx Platform and supported external exchanges.

Its purpose is to allow validated trading decisions to interact with exchange infrastructure through controlled API-based connections.

## Purpose

The connectivity layer is designed to support:

- exchange account connection
- market data access
- order submission
- execution status monitoring
- connection health checks
- controlled trading permissions

Noryx does not require direct custody of user funds in order to operate through exchange APIs.

## API-Based Connectivity

Supported exchanges are connected through API credentials generated by the user directly within the exchange account.

Where supported, users should configure only the minimum permissions required for trading functionality.

Recommended permissions may include:

- read market/account information
- place and manage orders

Withdrawal permissions should remain disabled whenever they are not required.

## Connection Flow

Typical connection flow:

User Exchange Account  
↓  
API Credentials  
↓  
Noryx Connect  
↓  
Validation & Permission Checks  
↓  
Noryx Platform

The platform should verify that required permissions and connectivity are available before enabling trading functionality.

## Credential Handling

Exchange credentials are sensitive information.

The platform should never expose API secrets in the user interface after initial configuration.

Security controls may include:

- encrypted transmission
- restricted backend access
- controlled credential storage
- permission validation
- secrets management
- access logging

Public documentation does not disclose internal credential storage architecture.

## Permission Principle

Noryx follows a least-privilege approach where technically supported.

This means API credentials should only include permissions required for the intended functionality.

For trading connections, withdrawal access should not be enabled unless explicitly required by a future feature.

## Connection Status

The platform may display connection states such as:

- Connected
- Disconnected
- Authentication Failed
- Permission Error
- Exchange Unavailable
- Reconnection Required

These states help users understand whether their exchange integration is currently operational.

## Order Execution

When a trading decision passes through the Quant Engine and Risk Engine, the Execution Layer may submit an order through the connected exchange API.

Typical flow:

Validated Signal  
↓  
Risk Approval  
↓  
Execution Request  
↓  
Exchange API  
↓  
Order Response  
↓  
Execution Status

The exchange remains responsible for actual order matching and execution.

## Execution Limitations

Real-world execution may differ from theoretical or simulated results because of factors such as:

- slippage
- liquidity
- latency
- order-book depth
- exchange outages
- partial fills
- minimum order sizes
- rate limits
- network interruptions

## Exchange Availability

Connectivity to an exchange does not guarantee uninterrupted service.

External exchanges may experience:

- maintenance
- degraded performance
- API outages
- trading restrictions
- rate limiting
- authentication changes

Noryx may temporarily suspend execution when required connectivity conditions are not satisfied.

## Security Recommendations

Users should:

- create dedicated API credentials for Noryx
- enable only required permissions
- keep withdrawal permissions disabled
- use strong exchange account security
- enable multi-factor authentication
- rotate credentials if compromise is suspected
- immediately revoke credentials that are no longer in use

## User Control

Users remain responsible for their exchange accounts and credentials.

API access can normally be revoked directly from the exchange account at any time.

## Supported Exchanges

The list of supported exchanges may evolve over time.

Only integrations explicitly shown as supported within the Noryx Platform should be considered compatible.

Do not assume that an exchange is supported based solely on generic API compatibility.

## Privacy

Exchange-related information should never be exposed publicly.

Noryx does not publish:

- user balances
- API credentials
- exchange account identifiers
- private order identifiers
- individual trading activity
- personally identifiable exchange data

## Monitoring

Connection health may be monitored through the Noryx Platform and Noryx Systems Status.

Public status information should remain aggregated and must not expose individual user connections.

## Proprietary Infrastructure

This documentation describes the public conceptual architecture of exchange connectivity.

The following are intentionally not disclosed:

- production endpoints
- internal network architecture
- credential storage implementation
- private authentication logic
- internal exchange adapters
- infrastructure secrets
