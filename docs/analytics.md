# Noryx Analytics

Noryx Analytics is the performance and system-observation layer of the Noryx Platform.

Its purpose is to provide structured visibility into signals, trades, strategy behavior, risk events and system performance.

## Purpose

Noryx Analytics helps users and operators evaluate how the platform behaves over time.

It may include:

- signal history
- trade history
- confidence analytics
- P&L analysis
- drawdown metrics
- market regime distribution
- risk events
- execution outcomes
- system statistics

Analytics are intended to support measurement and transparency.

## Data Environments

Noryx may separate analytics by environment.

Possible environments include:

### Live

Data generated by real trading activity executed through connected exchange infrastructure.

### Demo

Simulated execution using live or delayed market conditions without real capital exposure.

### Backtest

Historical simulation based on past market data and predefined strategy logic.

These environments should not be combined without clear labeling.

## Signal Analytics

Signal analytics may include:

- total signals
- long signals
- short signals
- rejected signals
- average confidence
- confidence distribution
- market regime
- directional edge
- execution decision

Signal data can help evaluate how frequently the system identifies potential opportunities.

## Trade Analytics

Trade analytics may include:

- total trades
- winning trades
- losing trades
- average winner
- average loser
- average holding time
- best trade
- worst trade
- profit factor
- expectancy

Only metrics supported by actual recorded data should be displayed.

## Performance Metrics

Depending on available data, Noryx Analytics may calculate:

- cumulative P&L
- net P&L
- win rate
- maximum drawdown
- current drawdown
- average trade return
- equity curve
- directional performance

Performance data should always be interpreted in the context of the underlying environment.

## Drawdown

Drawdown measures decline from a previous performance peak.

Possible metrics may include:

- current drawdown
- maximum drawdown
- drawdown duration

Drawdown is an important risk metric because profitability alone does not fully describe strategy behavior.

## Confidence Analytics

Signal confidence can be analyzed over time.

Example confidence ranges:

- 50–60
- 60–70
- 70–80
- 80–90
- 90+

This can help evaluate whether strategy outcomes vary across different signal-quality levels.

A higher confidence score does not guarantee a profitable result.

## Market Regime Analytics

Performance can also be analyzed by market environment.

Possible regime categories may include:

- trending
- ranging
- expansion
- compression
- high volatility
- low volatility

This can help determine how strategy behavior changes across different market conditions.

## Directional Analytics

Long and short activity may be evaluated separately.

Possible comparisons include:

- trade count
- win rate
- average P&L
- average confidence
- holding time

Directional analysis can help identify asymmetry in system behavior.

## Risk Analytics

Where supported by recorded data, Noryx Analytics may track:

- rejected trades
- Risk Engine interventions
- confidence threshold failures
- volatility filter activations
- exposure limit events
- execution blocks

These events can provide insight into how often risk controls prevent execution.

## Execution Analytics

Execution-related metrics may include:

- submitted orders
- filled orders
- rejected orders
- partial fills
- execution latency
- slippage

Availability depends on exchange data and platform implementation.

## Data Freshness

Analytics should display the most recent available data timestamp where possible.

Examples:

Last Updated  
Last Trade  
Last Signal  
Last Processing Cycle

Stale or incomplete data should be clearly identified.

## Transparency

Noryx Analytics should clearly distinguish:

- live results
- simulated results
- backtest results

Backtested or simulated performance must not be presented as live trading performance.

## Data Limitations

Analytics may be affected by:

- incomplete historical data
- missing exchange responses
- connectivity interruptions
- market-data gaps
- execution differences
- fee assumptions
- slippage
- strategy-version changes

Users should consider these limitations when interpreting performance metrics.

## Strategy Versions

Performance should be associated with the relevant strategy version whenever possible.

Changes to strategy logic can make historical results less directly comparable.

Example:

Strategy: Noryx Quant Strategy  
Version: V6.2

## Privacy

Public analytics must not expose:

- user identities
- account balances
- API credentials
- exchange account identifiers
- private order IDs
- confidential strategy parameters
- private user trading history

Aggregated public statistics should be used where appropriate.

## Integration with the Noryx Platform

Noryx Analytics can receive information from several platform layers:

Market Intelligence  
↓  
Quant Engine  
↓  
Risk Engine  
↓  
Execution Layer  
↓  
Noryx Analytics

This allows the platform to measure both decisions and outcomes.
